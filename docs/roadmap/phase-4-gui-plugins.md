# Phase 4：GUI 原生插件系统（B 轨）

- 状态：设计已定稿（2026-10-28，市场形态见 ADR-0016），P0 实现中；依赖 Phase 2 + Phase 3 验收通过
- 参考估时：4~8 周
- 关联：ADR-0004/0016；architecture/04 §3/§4

## 1. 目标（一句话）

本项目自有插件生态闭环：第三方可用 TSX 写带界面的插件，经 manifest 声明 → 签名包分发 → 沙箱运行 → 授权 → 在主窗口指定槽位渲染，全程安全可控；并用自家功能插件化自证扩展面完整。

## 2. 范围

### 做
- manifest schema 2（B 轨；A 轨保持 schema 1）：能力声明（fs/net/exec）、slot 声明、权限级别、命名空间 id
- B 轨运行时：QuickJS + NSH 栈；slot 白名单（toolCard/panel/composerTrigger/entryExtra/theme 起步）；渲染动作白名单词汇表；越界即拒
- 权限 GUI：能力声明的可视化授权界面（替代 Phase 2 的 CLI 简版）；授权持久化与撤销
- 签名与分发：ed25519 签名包校验、装载、热更；devkit CLI（check/pack/sign）
- 插件市场：静态索引（HTTPS JSON）、发现/主题/收藏/已安装/已屏蔽/高级页签、分类与搜索、卡片直接安装、离线缓存
- 市场治理：申请收录外链、本地导出诊断；不自建账号/支付/评分/评论后端
- 诊断与审计：插件行为（被拒能力、降级）可查看
- **自证插件**：把一个本项目自有功能（候选：会话搜索面板或 todo 面板）做成 B 轨插件

### 不做
marketplace 交易与账号、评分/评论后端；跨插件通信总线；移动端；A 轨矩阵变更

## 4. 验收场景

| # | 场景 | 通过标准 |
|---|---|---|
| D1 | 示例插件全链路 | 从 TSX 源码 → devkit 打包签名 → 安装 → 授权 → slot 渲染 → 热更升级，全程按文档操作可复现 |
| D2 | 自家功能插件化 | 自证插件与内置功能体验无差别，且其存在不依赖任何内置特权 |
| D3 | 安全专项 | 未签名包拒载；未声明能力调用被拒并审计；沙箱逃逸用例（直接访问 fs/net）全部失败；权限撤销即时生效 |
| D4 | 稳定性 | 插件死循环/崩溃不影响主应用（隔离 + 超时）；卸载后无残留进程 |
| D5 | 接缝核对 + CI 全绿 | architecture/03 达标；B 轨 API 有版本契约文档 |
| D6 | 市场发现 | 静态索引可加载、缓存与离线；分类/搜索/收藏/屏蔽持久化；卡片安装与本地安装走同一签名与挡位校验 |
