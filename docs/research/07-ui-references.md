## 1. 用途与使用方法

为桌面壳**视觉精修**（产品级 UI）提供参考方向。本清单是素材池，不是设计稿：

1. 浏览图片，**划掉**不喜欢的产品/风格，把自己找到的参考随时补进来（链接或本地文件路径均可注明）；

3. **只借鉴布局语言与质感方向，不复制任何产品的具体视觉**。

### 4.1 组件级：shadcn AI Elements `Trace`（工具过程呈现，所有者指定 2026-10-27）

所有者明确指定：**AI 会话每一步动作的 UI 呈现参照 Trace 组件**（[ui.shadcn.com/docs/components/base/trace](https://ui.shadcn.com/docs/components/base/trace)）。

**组件词汇**：Trace = 行列表；每行 = 图标 + 标题 + 次要描述（计数/耗时，不截断）；标题单句、运行中带 shimmer 微光动画；行可折叠展开 / 打开对话框或侧滑面板。四种状态语义：

| 状态 | 语义 | Timo 对应 |
|---|---|---|
| `pending` | 未开始/等待 | **待审阅的工具调用**（K2 审阅接缝：pending 行展开 → diff 审阅面板，形态天然契合） |
| `running` | 进行中（现在时） | 工具执行中（标题 shimmer + 停止按钮所在行） |
| `none` | 已完成（过去时，"Ran …"） | 工具过程折叠卡（第 4 批已交付的形态） |
| `error` | 失败（标题陈述错误） | 工具失败行 + 错误摘要 |

**与我们现状的关系**：第 4 批已交付的"工具过程折叠卡"是 `none/error` 两态的朴素版；Trace 提供了更完整的词汇表——补上 `pending`（审阅等待）与 `running`（shimmer 动效）两态、每行图标、描述与标题的分工（计数/耗时放描述不截断，主句放标题可截断）。**升级方向记入视觉精修批次的组件清单，不回改 Phase 3 已交付批次。**

**两点注意**：① Trace 的模式族（Tool/Plan/Terminal/**Subagent**/Test Results/Reasoning…）恰好覆盖我们规划中的功能面——Subagent 模式即 Phase 3.5 D6 验收的呈现层蓝本；② shimmer 动效在 gpui-kit 的动画能力需实现期验证，降级方案为状态图标。


1. **左会话列表 + 中内容流 (+ 右详情/审阅) 是绝对主流**——我们的 248 侧栏 + 聊天流 + 400 审阅面板与全部三类产品一致，**骨架不需要推翻**；
2. **会话即一级对象**：Zed 的"New Thread"置顶按钮、Claude/ChatGPT 的会话列表，与我们的"新建任务 + 项目分组"同构；
3. **暗色优先、明暗双主题标配**：四家默认暗色；我们已走 gpui-kit 语义 token，方向一致；
4. **命令面板是效率标配**：Raycast/Linear 的 cmdk 模式是 Phase 3 命令面板批次的现成蓝本；
5. **设置页两栏模式**：左分组右内容、权限逐项开关（ChatGPT 设置页、Zed providers）——对应我们设置/钥匙串批次与"审批档位"设置面；
6. **状态反馈进头部与状态栏**：运行中徽章、进度、用量（Linear 状态徽章、我们 Chat head 的进度条设计一致）；
7. **块状过程呈现**：Warp 的 block、各家工具调用的折叠卡——对应我们工具过程 trace 的折叠卡，视觉精修时的重点打磨对象；组件级蓝本见 §4.1（所有者指定 Trace）。

## 8. 所有者视觉方向 v1（2026-10-27）

> 本节是所有者口述方向的忠实记录，**先于参考筛选**，是 §2~§4 清单取舍的基准。待澄清项在设计稿前确认。

### 8.1 总基调

**极简灰白**——亮色中性系，非暗色优先。

### 8.2 窗口骨架："画布 + 浮动卡"，无顶栏无底栏

- **取消顶栏（标题栏）与底栏（状态栏）**：窗口即画布，内容以卡片浮于画布之上。
- **左栏**：灰色实底（贴边，不收缩）；内容 = **新建任务** + **工作区折叠树**（工作区 → 会话两级管理）。
- **中栏 + 右栏**：白色卡片；相对窗口**上/右/下收缩 4px**（灰底从缝隙透出）；卡片外圆角**与窗口圆角同心**；中右两卡**间距 4px**；**微弱悬浮**阴影 + **发丝线压边**。

### 8.3c 会话内视图（方向图 2026-10-27 第二批：[聊天视图](assets/direction-chat-view.png) / [浏览器面板](assets/direction-chat-browser-panel.png)）

- **内容区轻页头**：`📁 会话标题` 居左 + 右栏开关/窗口控制浮动居右——是画布内页头，非传统顶栏（与 §8.2 无顶栏不冲突）。
- **每轮过程汇总行**：`✓ 已工作 0 分 3 秒`——可折叠；对应设置项"折叠工具执行过程"（开启=每轮收为计时长，关闭=轮次保持展开、仅工具行即收）。
- **轮次整体收叠两态**（方向图 2026-10-27：[收起态](assets/direction-turn-collapsed.png) / [展开态](assets/direction-turn-expanded.png)）：**点击汇总行即整轮收起/展开**——收起态只剩汇总行一行（用户消息 → 汇总行 → 下一条用户消息，中间全收）；展开态显示全部过程行（思考/搜索/回声/子代理/终端…，行 hover 出展开箭头）。汇总行记录**结束态**：`✓ 已工作 3 分 2 秒 · 已停止 · ⓘ 1 个问题`（时长 + 结束方式[完成/已停止] + 问题数）。
- **过程行内形态**（§4.1 Trace 词汇的具象化）：`💡 思考 · 1s` 浅色小行；工具行（`🔍 搜索 文件读写·编辑 搜索 git 撤销 恢复 定时任务`）；行内 `⌄` 展开按钮。
- **单步详情展开**（第三层密度，方向图 2026-10-27：[assets/direction-step-detail.png](assets/direction-step-detail.png)）：过程行点开即铺开全文——思考行展开为**多段推理全文**；工具行展开为**退出码 + 输出代码块（可滚动）+ `› 原始数据` + `⧉ 复制调用`**；失败步骤展开**红色错误详情全文 + 命令回显**。三层信息密度：轮次收叠（汇总行）→ 过程行（一行一步）→ 单步详情（全文/输出）。
- **消息**：用户右对齐浅灰胶囊；助手无气泡直接排版；hover 出复制/编辑图标 + 时间戳；长消息自动折叠（设置项）。

- **安装闭环**：工作区写 bundle → `plugin_manager` `install_bundle` 装进当前 profile（重启存活、全会话生效）；非完全访问档**每次安装需审批**。UI 插件默认落 Web UI，先 `Slots.listSubTree` 查槽位再注册——slot 思想与我们 B 轨白名单同构。
- **工程纪律可借鉴**："先交付能跑的最小插件，装上后用本体验证"，明令禁止先做 mock/预览页/设计变体；知识源优先级 = 检视工具 → 包 README → `.d.ts`；桌面端技能与模板在 app.asar 内，须先拷到工作区再改。
- 框架本体 = **Cordis**（Koishi 生态插件系统，vendored 于 `vendor/cordis`）——插件即 npm 包，pnpm 管理。
