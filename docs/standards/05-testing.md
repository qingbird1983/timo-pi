# 规范 05：测试与验收

- 状态：定稿
- 日期：2026-10-26

## 1. 测试分层

| 层 | 对象 | 手段 |
|---|---|---|
| 单元 | 各 crate 内部逻辑 | Rust 内联 `#[test]` |
| 集成 | crate 间契约（工具管线、会话读写、事件总线） | `crates/*/tests/` |
| 协议适配 | timo-ai 与真实 API 的行为等价性 | **fixture 录制回放**（禁 CI 直连 LLM） |
| UI 集成 | gpui-kit 界面交互 | `#[gpui_kit::test]` 无头窗口（Phase 3 起） |
| 端到端 | phase 验收场景 | 人工按场景执行 + 可脚本化部分脚本化（scripts/e2e-*） |

## 2. 硬性测试义务（不达不算完成）

1. **协议 fixture**：每个协议适配覆盖 正常流式/工具调用/错误与重试/取消 四类路径；fixture 文件入 `fixtures/protocol/`，来源与抓包日期在文件头注明。
2. **会话格式兼容**：`fixtures/session/` 存放历史版本样例；CI 断言"旧样例可读且语义不变"（Phase 1 格式定稿后生效）。
3. **接缝回归**：architecture/03 各接缝的检查点写成可执行断言或专项测试（如：事件订阅者无需改动 agent 循环即可编译——以编译期示例测试保证）。
4. **崩溃安全**：kill -9 / 断电模拟（截断写入）后 会话文件可读（Phase 1 A3 的自动化版）。
5. **沙箱/权限**：越权用例清单化（Phase 2/4），全部必须"拒绝且留痕"。

## 3. 确定性与可复现

- 时间、id、随机源一律注入（可替换时钟），保证会话与日志可复现。
- 禁止测试访问网络、依赖外部服务状态；LLM 相关测试一律回放。

## 4. 验收流程

- 每阶段验收 = 逐条执行 phase 文档"验收场景" + 《阶段进度报告》记录结果。
- 验收一票否决项：该阶段 phase 文档中标注"一票否决"的场景（如 Phase 2 的钩子语义 B3）；未通过不得打 `phase-N.end` tag。
- 覆盖率：内核 crates 行覆盖率目标 ≥ 70%（报告披露、不设卡）；不达标的模块在进度报告说明原因。

## 5. 回归纪律

- 修复缺陷必须先写"能复现的失败测试"，再修复；该测试永久保留。
- flaky 测试即修或隔离（`#[ignore]` + issue），禁止长期带 flaky 绿灯。
