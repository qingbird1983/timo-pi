# 规范 07：AI 协作规范

- 状态：定稿
- 日期：2026-10-26
- 关联：AGENTS.md（入口摘要）；standards/01~06（各领域细则）

## 1. 冷启动原则

本项目由 AI 会话接力开发，**任何会话不得依赖"上一个会话的记忆"**：开工时按 AGENTS.md 顺序读文档；工作中产生的新事实/决策/风险必须当场落盘（research / ADR / design / 看板），不允许"留在对话里"。

## 2. 会话开工清单

1. 读 `AGENTS.md` → `docs/README.md` → 当前 phase 文档 → `standards/` 相关篇。
2. 确认当前阶段状态（README 看板）与本会话任务的关系：是推进当前阶段，还是维护性修改。
3. 检查工作区干净（`git status`）；从 main 拉新分支。
4. 若发现文档与代码/事实不符：**先修文档或提 ADR**，再继续任务。

## 3. 阶段生命周期中的 AI 职责

| 时点 | 职责 |
|---|---|
| 开工 | 核对开工前置条件（phase 文档 §"开工前置条件"）；不满足则先补文档 |
| 设计 | 产出/修订 `docs/design/phase-N/` 并转定稿；重大取舍写 ADR |
| 实现 | 遵守 standards/04/05/06；feature 分支；小步提交 |
| 验收 | 逐条执行验收场景（含一票否决项）；接缝核对（architecture/03） |
| 收尾 | 《阶段进度报告》→ README 看板 → CHANGELOG → tag `phase-N.end` → 更新 AGENTS.md 阶段指针 |

## 4. 对所有者的沟通规则

- 所有者不读代码：汇报一律用《阶段进度报告》与 CHANGELOG 的"非技术语言"，避免行话；必须使用术语时链接 `docs/glossary.md`。
- 需要所有者决策的事项（如许可证、平台优先级）集中列在 README"待决策"表，并在 CHANGELOG 条目中提醒。
- 坏消息优先：风险、延期、验收未过必须如实、尽早写入进度报告，禁止"报喜藏忧"。

## 5. 外部代码纪律

- **PI-Desktop（LGPL-3.0）**：严禁复制/翻译/结构性照搬其源码；只允许参考其公开文档描述的设计思路。涉及借鉴点的实现必须为本项目原创并注明"思路参考 docs/research/04"。
- **pi-flash（GPL-3.0）**：与 PI-Desktop 同级处理——严禁复制/翻译/结构性照搬其源码与文档文字；其 gpui 陷阱笔记、架构方法论、插件系统设计**只吸收思路与事实**，实现须为本项目原创并注明"思路参考 docs/research/05"。
- **pi 上游**：可阅读其源码理解行为与协议（互操作目的），但禁止整文件复制；移植行为时以 fixture 测试固化理解，而非复制实现。
- 引入任何第三方代码片段（SO/博客等）须满足依赖准入同等的审查与登记。

## 6. 范围纪律

- 只做当前阶段 phase 文档"做"清单内的事；发现高价值超出项 → 登记 backlog（roadmap §3）或新开 ADR，**不顺手实现**（ADR-0008 同款纪律）。
- 规范冲突时优先级：安全（06）> 测试硬义务（05）> 文档先行（03）> 其余。

## 7. .agent 交接与沉淀（每轮会话收尾必做）

规则全文见 `.agent/README.md`，预算受 `standards/08` 约束。摘要：

1. **重写** `.agent/CONTEXT.md`（覆盖式，模板 A）——下一轮会话的第一站。
2. **归档** handoff（≤80 行/份，滚动保留 5 份）。
3. **沉淀**：新坑 → pitfalls（一坑一文件，先查重）；新方法 → skills（一主题一文件）；**教训当轮提取，未提取即交接失败**。
4. **体量核对**：CONTEXT ≤150 行、.agent 全目录 ≤40 文件，超标当轮清理。

正式知识（应让所有未来会话永久知道的）归宿是 docs/（ADR/架构/规范），.agent 只放过程与经验。
