# 规范 06：安全与隐私

- 状态：定稿
- 日期：2026-10-26

## 1. 威胁模型（一句话）

本项目运行在本机用户全权限下，且会执行三方代码（编排扩展、GUI 插件）与模型驱动的工具（改文件/跑命令）——安全设计围绕"**默认最小能力，一切显式授权**"。

## 2. 仓库卫生

- 密钥/凭证/令牌**严禁**入库：`.env*` 已 gitignore；示例文件只允许 `.env.example` 占位符。
- 个人绝对路径不入库（文档引用外部项目用 GitHub URL 或相对描述）。
- 提交前自查 + CI 占位检查（Phase 1 建立简单 secret 扫描脚本）。
- 一旦发现密钥泄露入历史：立即吊销该密钥，再清理历史，并记录事故。

## 3. 凭证存储

- API key 等凭证：桌面端入**系统钥匙串**（Phase 3 起）；CLI 早期阶段允许权限收敛的本地配置文件（0600 等价），Phase 3 后统一钥匙串。
- 配置文件中只存**引用**（如 `keyRef: keychain:timo/anthropic` 或 `$ENV:ANTHROPIC_API_KEY`），不存明文。
- 日志与诊断输出必须脱敏（key/token/授权头一律遮蔽）。

## 4. 插件与扩展沙箱（两轨一致原则，细节见 architecture/04 §3）

- 默认无能力：文件、网络、执行、环境变量均须 manifest 声明 + 用户逐项批准（双闸）。
- fail-closed：未声明 = 拒绝；声明全树写删 = 拒绝；`.env*`/SSH 凭证/`.git/**` 硬拒。
- JS 执行环境默认无宿主能力，能力以显式注入的受控函数提供；禁止动态加载代码。
- 高风险类别单列（编排扩展等同 agent 本体权限的成员、渲染 slot），UI 上明确标注信任级别。
- 每次能力拒绝与高风险授权必须留审计记录，用户可查。

## 5. 工具执行安全（内核内建）

- 工具信任分级（只读/写入/执行）+ 项目信任概念（MVP 起即区分，向 pi 的 project trust 语义看齐）。
- 危险操作（删除、覆盖、不可逆命令）必须经用户确认通道；确认策略可配置但默认从严。

## 6. 供应链

- 依赖准入按 standards/04 §5；lockfile 入库；升级走窗口化（NSH/gpui-kit 尤其）。
- Phase 1 起 CI 含 `cargo deny` 类检查（许可证冲突 / 已知漏洞源）。

## 7. 事件与上报

- 项目默认**零遥测**；未来如加，默认关闭 + opt-in + ADR。
- 安全漏洞报告渠道：暂以仓库 issue 私密方式（所有者决策后补充正式政策，README 待决策项关联）。
