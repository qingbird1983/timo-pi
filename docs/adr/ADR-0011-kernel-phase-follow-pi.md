# ADR-0011：内核阶段严格对齐 pi，忠实复刻；创新延后至项目稳定

- 状态：定稿
- 日期：2026-10-26
- 关联：ADR-0002/0005/0006/0007；roadmap/00 §3；roadmap/phase-1、phase-2；standards/07 §6

## 背景

项目本质是复刻 pi 内核。所有者确立硬约束：**内核阶段方向不得偏离 pi，严格按 pi 的方向走；项目稳定后才考虑自有设计创新**——否则范围蔓延与设计争论会"收不住"。

## 决策

1. **Phase 1~2 为"忠实复刻期"**：内核与编排兼容层的功能集、行为语义、数据形态以 pi 既有实现为**唯一蓝本**——"pi 怎么做，我们就怎么做"。
2. **对齐 = 语义对齐，不是逐行照抄**：外部可观察行为（输入→输出、会话形态、工具语义、扩展 API 签名与语义、错误与取消行为）与 pi 一致；内部实现是 Rust 原创，且始终受许可边界约束（AGENTS 铁律 6：pi 上游可读不可抄）。
3. **允许的偏离仅限三类白名单**（除此之外一律按 pi）：
   a. 语言/运行时必然差异（Rust、无 Node）导致的实现方式不同；
   b. 既有 ADR 已定的载体替换：rmcp（ADR-0005）、自研会话格式（ADR-0007）、QuickJS 宿主（ADR-0006）、无 TUI（ADR-0002）；
   c. 本仓库 standards 的硬性要求（安全/测试/体量/取消语义）。
4. **创新冲动一律"记录不执行"**：认为 pi 某处设计不佳、或想到更优方案 → 写入 roadmap §3 backlog 或开 ADR 排期到 Phase 5+；**当前阶段仍按 pi 的方式实现**。
5. **Phase 3~4 的定位**：桌面壳与 B 轨插件面是既定规划的自建层（pi 无对应物），按既有 ADR 执行，属计划内而非本约束所指"创新"；但不得借机改动内核行为语义。
6. **解禁条件**：Phase 4 验收通过、项目进入稳定维护后，创新提案方可进入排期；届时每项独立 ADR + 独立条目，不与复刻工作混排。

## 理由

- pi 就是规格说明书：验收可判定（行为对照），消除设计争论空间；
- pi 已踩过的坑是现成答案，自创设计等于重交学费；
- AI 会话最容易"顺手优化"导致范围失控——本约束给出明确的否决依据，backlog 是创新冲动的强制去处而非摆设。

## 后果

- Phase 1/2 验收增加"行为对齐"维度：场景执行时以 pi 对应行为为对照（对照入口表见 research/01 §5）。
- 执行判据（供 AI 与评审使用）：遇到"我想换个做法"，先问三问——pi 是不是这么做的？偏离是否落在三类白名单内？是不是已有 ADR 授权？三问皆否 → 记 backlog，按 pi 做。
- 本约束由所有者发起，修订或解禁须所有者明确同意（新 ADR 取代本篇）。
