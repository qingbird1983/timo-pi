# ADR-0001：内核采用 Rust 全量自研，不引入 Node 运行时

- 状态：定稿
- 日期：2026-10-26
- 关联：ADR-0005、ADR-0006、ADR-0007、ADR-0009；research/01、research/04

## 背景

目标是对齐 pi 内核能力（agent 循环、LLM 协议、工具、会话、扩展）。参考项目 PI-Desktop 的路线是把 pi 的 npm 包嵌入 Node sidecar 复用（其 ADR 明确否决全量重写）；本项目仓库愿景为 Rust 自研。

## 决策

用 Rust 从零实现内核全部能力，**任何阶段都不引入 Node.js 进程**。

## 理由

- 单运行时：消除 PI-Desktop 承受的"双运行时边界税"（持久化所有权分裂、进程间崩溃/审批/恢复语义复杂，其 spec 大量篇幅在填这类坑）。
- 分发干净：桌面端与 CLI 都是单一原生可执行文件，无 Node 打包与版本地狱。
- 自有会话格式与权限模型可一步设计到位，无上游包袱。

## 备选（否决）

- **Node sidecar 复用 pi**（PI-Desktop 路线）：开发快、追上游省力；否决——双运行时税、patch 上游 dist 不可持续、桌面分发被迫捆绑 Node、与本项目愿景冲突。

## 后果

- 正面：架构统一、长期维护成本低、可控性强。
- 负面：自研成本高——内核 MVP 约 6~10 周、全功能对齐累计 5~7 人月（研究 01）；协议正确性需自建 fixture 测试保障。
- 风险对策：MVP 收窄范围（2 种协议）；MCP 用官方 rmcp 不自研；关键接缝按 `architecture/03-critical-seams.md` 预留防返工。
