# ADR-0013：内核深化阶段立项——复刻范围扩展到交互逻辑与提示词工程

- 状态：定稿
- 日期：2026-10-27
- 关联：ADR-0011（内核期对齐 pi）、ADR-0007（会话格式）、ADR-0009（内核即库）；roadmap/phase-3.5；research/06

## 背景

2026-10-27 对 pi 1.4.0 `coding-agent/src/core/` 的缺口审计发现：Phase 1/2 已复刻循环、工具管线、会话、协议、MCP、扩展钩子（约等于 pi 的"薄核心循环 + 编排钩子"），但以下"灵魂件"缺失——项目上下文加载（AGENTS.md）、system-prompt 完整组装机器、skills、compaction、cache 统计/预热、usage 聚合、provider-composer/virtual-models、prompt-templates、无头模式。其中 skills、cache-warmer、provider-composer、prompt-templates 四件此前**未在任何阶段或 backlog 登记**，违反"一切延后必须留痕"的治理规则。

所有者同时确认两点方向判断：

1. pi 的产品价值主要在编排层与交互数据层，不在薄循环；只复刻循环等于"仿了皮"。
2. **不要 pi 的 TUI 皮，但产品交互逻辑必须复刻**——TUI 里承载的交互语义（消息队列、工具过程、审阅、compaction 时机等）与数据流向，正是 GUI 壳要继承的"里子"；换皮不换理。

## 决策

1. **新增 Phase 3.5「内核深化」**，位于 Phase 3 整体完工之后、Phase 4（GUI 插件）之前。Phase 4 编号**保持不变**（ADR 只增不改，既有文档对"Phase 4 = GUI 插件"的引用不作回改）。
2. **复刻范围语义扩展**（对 ADR-0011 的延伸而非偏离）：对齐对象从"代码行为语义"扩展为"行为语义 + 产品交互逻辑 + 数据流向 + 提示词工程"。TUI 源码（modes/interactive/）作为交互逻辑蓝本阅读，其皮肤实现仍不移植。
3. **缺口归位**：上述缺失项按 P0/P1/P2 三级纳入 Phase 3.5 范围（清单见 phase-3.5 文档 §3）；backlog 中 compaction、codemode、print/json 模式三条升格至该阶段。
4. **验收标尺**：以 pi 官方 `examples/extensions/subagent` 为行为蓝本自研等价扩展（MIT 只读不抄）——子代理工具注册、子进程无头隔离运行、.md 代理定义、用量汇报，跑通即证明编排层到位。
5. **调查先行**：research/06（pi 交互逻辑 / 数据流向 / 提示词工程调查）为本阶段首个交付物，定稿后才允许详设与写码。

## 后果

- 正面：内核与 pi 的差距从"能跑"收敛到"生态可移植"；桌面壳获得真正的产品里子；四件未登记缺口归位，治理闭环。
- 代价：Phase 4（GUI 插件）顺延约 3~6 周；Phase 3 期间新增一篇调查与一份阶段文档（在体量预算内）。
- 风险：交互逻辑调查若停留在"读代码"层面会产生新的一手依赖——对策：research/06 产出物定义为行为语义清单与数据流图，逐条挂验收场景。
