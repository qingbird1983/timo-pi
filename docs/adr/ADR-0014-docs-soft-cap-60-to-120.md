# ADR-0014：docs/ 文档总数软上限 60 → 120

- 状态：定稿
- 日期：2026-10-27
- 关联：standards/08 §2/§6；standards/09 §2（过严信号）、§4（规则级修订）

## 背景

standards/08 设的 docs/ 文档总数软上限 60 篇已被突破且持续扩大：Phase 1 收尾 47（达标）→ Phase 3 收尾 60（顶格）→ Phase 3 报告 65 → Phase 3.5 报告 69（豁免登记，整合评审挂"待办"两次）→ 2026-10-27 实测 **75 篇**。规则触发了"整合评审"却从未执行——上限与项目现实脱节，属 standards/09 §2 的过严/失效信号；所有者 2026-10-27 裁定："上限 60 估计不够，至少还要翻一倍"。

**结构性动因**（为何会超，而不是谁违规）：

1. **行数预算逼高篇数**：单篇设计稿 ≤500 行的规则强制按模块拆分——`design/` 已 31 篇（占 41%），Phase 3 一期贡献最大。行数与篇数两条预算互相挤压，篇数预算必须给拆分留空间。
2. **两类集合只增不减是设计使然**：ADR 只增不改（现 13 篇）、research/ 结论冻结新调查新开篇（现 8 篇），每阶段稳定各 +1~3 篇，长期单调上涨。
3. **计数口径从未定义**：图片资产（research/assets/ 16 张）是否算"一篇"没有规定。

## 决定

1. docs/ 文档总数软上限 **60 → 120 篇**（所有者"至少翻一倍"，取整 120）。
2. 计数口径写明：**按 docs/ 下 `.md` 文件数计，图片等资产不计**。
3. 超限处置不变：仍是**触发整合评审**（合并碎片、归并过时篇），不是禁止增长。
4. 历史阶段报告中的旧数字是冻结记录，不改。

## 后果

- 120 ≈ 当前 75 + Phase 4 与视觉精修批次的预估增量（design/phase-4 拆分 + ADR/research 常规增长）后仍留整合余量；产品稳定期靠整合评审收敛篇数，**不依赖继续抬限**——再触顶时先做整合评审，其次才议新上限。
- 挂账两次的整合评审仍有效：进入 Phase 4 前执行一次（删除面需所有者确认），与新上限并行不悖。
- 同步修订：standards/08 §2 表行与 §6 模板中的数字、docs/README.md 的 ADR 区间登记。
