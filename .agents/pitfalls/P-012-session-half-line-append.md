# P-012 会话续写把崩溃残留半行拼成坏行

## 现象

进程被强杀（`kill -9`、任务管理器、断电）时，正在写的那一行可能只落盘一半。下次打开该会话**读取正常**（末行截断被丢弃），但**只要继续在这个会话里写入**，新 entry 会接在那半行后面，形成一条以 `\n` 结尾、内容非法的「中间行」。此后 `read_entries` 恒报 `CorruptEntry`，整个会话永久不可读。

## 根因

`SessionWriter::open`（`crates/timo-session/src/writer.rs:115-134`）做两件事：先用 `read_entries` 校验（读取端容忍末行截断，见 `reader.rs:32-39`），再以 `OpenOptions::new().append(true)` 打开文件续写。

问题在于：**读取端的容忍没有回写到磁盘**。内存里丢掉了半行，文件里还在；append 模式不会清理，新行直接拼接。

## 修复（待收债执行）

打开续写前，检查文件末尾是否有不完整行：从文件尾部向前找到最后一个 `\n`，若其后仍有字节则截断（`set_len`）。截断发生在校验之后、追加之前。

## 预防

1. **「容忍读取」与「安全续写」必须成对实现**——只做读取侧宽容，等于把损坏推迟到下一次写入。
2. 崩溃安全测试必须覆盖完整链路：写半行 → `open` → 追加 → 全量可读。现有测试只覆盖了读取侧的两种情形（`truncated_last_line_dropped`、`mid_file_corruption_is_error`），没有覆盖「恢复后继续写」。
3. 这是 architecture/03 接缝 #1（会话格式）的验收缺口：格式文档承诺「kill -9 后会话文件可读」，而该承诺在「恢复后续写」路径上不成立。
