# P-015 主动中断的原因被收尾错误覆盖

## 现象

GitHub Windows runner 上 codemode 的超时/取消用例偶发失败：一次报 `Script sandbox failed: Exception generated by QuickJS`，另一次报 `Error: cancelled`，都不是断言期望的 `Script timed out ...`。本机重复跑绿，单次 rerun 也可能绿。

## 根因

两条路径都把"真正的停止原因"交给了后续清理结果决定：

1. SHIM 安装在慢机器上可能已经越过 deadline；QuickJS 中断让 `install` 返回通用异常，而该错误没有按 deadline/取消状态重述。
2. 主循环按 deadline 主动收尾时会先取消子调用；脚本线程随后把子调用的 `cancelled` 当成最终错误交回，覆盖了 timeout 原因。

## 修复

- `codemode/sandbox/worker.rs`：安装期失败先查 deadline/取消，命中则用中断原因替代通用异常。
- `codemode/sandbox.rs`：主循环主动中断（`outcome = None`）拿到脚本线程结果后，强制用父取消/deadline 原因覆盖 `run.error`。
- 验证：同组 limits 用例重复 20 次全绿；CI 复跑为绿。

## 预防

1. **谁决定停止，谁写最终原因**：主动收尾方必须在最终结果上重述原因，不能让被取消的子操作或清理噪声当结论。
2. 有界等待实现里把"停止原因"与"停止后的残留"分开建模；不要用子任务的错误字符串反推父级为何停下。
3. 慢速 CI 上连续 rerun 命中不同用例 = 系统性时序问题，先归因再修，不要只靠重跑。
