# P-005：设计文档的模块格式与内嵌运行时不匹配

## 现象

设计 02 写产物为 ESM（`.mjs`），shim 也按 ESM 导入导出编写；实际内嵌 rquickjs 只能执行经典脚本，装载 `bundle.cjs` 时模块语法直接失败。夹具、文档、实现三方一起返工。

## 根因

- 选型阶段只确认了"打包成单文件"，没有在目标运行时里跑一个最小样例验证模块格式。
- 设计把 bundler 的能力当成运行时的能力；rolldown 能产出 ESM，不代表宿主能加载 ESM。

## 修复

- 产物改为 CJS `bundle.cjs`，shim 末尾按 CJS 包装；顶层 await 明确不支持（E106）。
- 设计 02、总体偏差表 D27、全部夹具与测试同步改为 CJS。

## 预防

- 涉及"运行时能执行什么"的设计，开工第一天先写探针：最小输入 → 目标运行时 → 记录实际行为，再把结论写进设计。
- 设计文档必须区分"打包器能力"与"宿主能力"，格式、模块系统、全局对象各写一行。
- 夹具第一次落地就必须走真实装载路径（不是只跑打包器），否则错误会拖到集成期。
