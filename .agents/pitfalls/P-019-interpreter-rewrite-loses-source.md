# P-019 用解释器脚本重写源文件会“先写后错”

## 现象

P1-d 拆分 `runtime/mod.rs` 时，用 Python heredoc 一次完成「读源码 → 抽取 `tick` → 重写文件」。
脚本在 `/tmp` 上失败（Windows 原生 Python 不认 MSYS 路径映射），但重写步骤已经执行：
`tick` 实现被删、没有备份，只能按先前读到的内容手工重建 `runtime/tick.rs`。

## 根因

- 解释器脚本是「读、改、写」一体的黑盒：任何中途异常都可能留下半成品，失败点与写入点顺序
  不可见。
- MSYS/Git Bash 的 `/tmp` 与 Windows 原生进程看到的路径不是同一个，脚本在 Windows 上不可移植。

## 修复

按原文重建 `tick.rs`（逐段对照先前读取的输出），再重跑编译确认；之后拆文件一律用编辑工具。

## 预防

1. 大段搬移用 Edit/Write：有 old/new 精确匹配，失败不会改文件。
2. 必须脚本化时，先写同目录临时文件并校验行数/关键字，全部通过再 `mv` 覆盖。
3. 不要在 Windows 项目里依赖 `/tmp` 给原生二进制用；临时文件放项目内的已忽略目录。
