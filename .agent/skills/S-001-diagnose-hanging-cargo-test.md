# S-001 定位挂起的 cargo test

## 适用场景

`cargo test` 整体或某个测试不结束（命令超时、无输出），但单跑部分测试正常。

## 前置条件

- 测试二进制能编译（`Finished` 行已出现）。
- 能访问仓库目录（日志必须落在工作区内；工具可能拒绝读系统临时目录）。

## 步骤

1. **先单跑最可疑的测试**：`cargo test -p <crate> --test <file> <name> -- --nocapture`，确认它是"过/挂/红"。
2. **串行跑并落日志**：`cargo test -p <crate> --test <file> -- --test-threads=1 > test.log 2>&1`；日志最后一行就是挂起的测试名。
3. **读代码找等待条件**：挂起的测试通常等一个永远不会发来的事件；检查被测路径是否真的产生该事件（本例：适配器从未发 Delta）。
4. **修复后跑全量**；若仍有并行挂起，重复步骤 2。

## 验证方法

- 单测、串行、全量三层都通过，且总耗时正常。
- 新增的"触发式取消"测试要带超时（`tokio::time::timeout`）或先断言触发事件存在，避免再次静默挂起。

## 失效条件

- 挂起源于编译/链接（进程未启动）或外部进程（MCP server 不响应）——先看日志头部与子进程。
